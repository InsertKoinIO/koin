import { Tabs, TabItem } from '@astrojs/starlight/components';

This page gives complete Koin setups for libraries most Android apps use (Retrofit with OkHttp, an authenticated client, Room, DataStore, a JSON serializer), injected dispatchers, a layered app structure, and Android-only patterns: choosing an implementation per build variant and declaring UI helpers that need the Activity. Library classes come from builders, so they are declared with provider functions. How that works (`create(::function)`, annotated functions) is explained in [Definitions](/docs/concepts/definitions/#classes-you-dont-own); this page only shows the Android setups. Patterns that work on every platform (collections, generics, decorators, providers) are in [Patterns](/docs/concepts/patterns/).

## Retrofit and OkHttp

{/* check: android-libraries-dsl, android-libraries-annotations, android-libraries-constructor */}

```kotlin
import retrofit2.http.GET
import retrofit2.http.Path

interface ApiService {
    @GET("users/{id}")
    suspend fun getUser(@Path("id") id: String): User
}
```

<Tabs syncKey="koin-style">
<TabItem label="Compiler Plugin DSL">

{/* check: android-libraries-dsl */}

```kotlin
import java.util.concurrent.TimeUnit
import kotlinx.serialization.json.Json
import okhttp3.MediaType.Companion.toMediaType
import okhttp3.OkHttpClient
import okhttp3.logging.HttpLoggingInterceptor
import retrofit2.Retrofit
import retrofit2.converter.kotlinx.serialization.asConverterFactory
import org.koin.dsl.module
import org.koin.plugin.module.dsl.create
import org.koin.plugin.module.dsl.single

fun okHttpClient(): OkHttpClient =
    OkHttpClient.Builder()
        .connectTimeout(30, TimeUnit.SECONDS)
        .readTimeout(30, TimeUnit.SECONDS)
        .addInterceptor(HttpLoggingInterceptor().apply {
            level = if (BuildConfig.DEBUG) HttpLoggingInterceptor.Level.BODY else HttpLoggingInterceptor.Level.NONE
        })
        .build()

fun retrofit(client: OkHttpClient, json: Json): Retrofit =
    Retrofit.Builder()
        .baseUrl(BuildConfig.API_URL)
        .client(client)
        .addConverterFactory(json.asConverterFactory("application/json".toMediaType()))
        .build()

fun apiService(retrofit: Retrofit): ApiService = retrofit.create(ApiService::class.java)

val networkModule = module {
    single { create(::okHttpClient) }
    single { create(::retrofit) }
    single { create(::apiService) }
}
```

Declare `OkHttpClient` and `Retrofit` as `single`: each one holds a connection pool and thread pools, and creating several wastes them. `BuildConfig.API_URL` is a `buildConfigField` you define per build type. The `Json` instance comes from the next section.

## Authenticated and public clients

Interceptors are ordinary classes, so Koin can pass them what they need. When only some calls must carry a token, keep two `OkHttpClient` instances and tell them apart with a [qualifier](/docs/concepts/qualifiers/):

{/* check: android-libraries-dsl, android-libraries-annotations, android-libraries-constructor */}

```kotlin
import okhttp3.Interceptor
import okhttp3.Response
import retrofit2.http.GET

interface TokenStore {
    fun token(): String?
}

class AuthInterceptor(private val tokens: TokenStore) : Interceptor {
    override fun intercept(chain: Interceptor.Chain): Response {
        val request = chain.request().newBuilder().apply {
            tokens.token()?.let { header("Authorization", "Bearer $it") }
        }.build()
        return chain.proceed(request)
    }
}

interface AccountApi {
    @GET("me")
    suspend fun me(): User
}
```

<Tabs syncKey="koin-style">
<TabItem label="Compiler Plugin DSL">

{/* check: android-libraries-dsl */}

```kotlin
import kotlinx.serialization.json.Json
import okhttp3.MediaType.Companion.toMediaType
import okhttp3.OkHttpClient
import org.koin.core.annotation.Named
import org.koin.core.qualifier.named
import org.koin.dsl.module
import org.koin.plugin.module.dsl.create
import org.koin.plugin.module.dsl.single
import retrofit2.Retrofit
import retrofit2.converter.kotlinx.serialization.asConverterFactory

fun authenticatedClient(auth: AuthInterceptor): OkHttpClient =
    OkHttpClient.Builder().addInterceptor(auth).build()

fun accountApi(@Named("authenticated") client: OkHttpClient, json: Json): AccountApi =
    Retrofit.Builder()
        .baseUrl(BuildConfig.API_URL)
        .client(client)
        .addConverterFactory(json.asConverterFactory("application/json".toMediaType()))
        .build()
        .create(AccountApi::class.java)

val authModule = module {
    single<AuthInterceptor>()
    single<OkHttpClient>(named("authenticated")) { create(::authenticatedClient) }
    single { create(::accountApi) }
}
```

</TabItem>

{/* check: android-libraries-annotations */}

A request for `OkHttpClient` with no qualifier still gets the public client from the previous section. Provide `TokenStore` from your own session code. In the Compiler Plugin DSL, `@Named` comes from the `koin-annotations` artifact, so add it to your dependencies.

## Coroutine dispatchers

Inject dispatchers instead of calling `Dispatchers.IO` in your classes, so that a test can replace them:

<Tabs syncKey="koin-style">

```kotlin
import kotlinx.coroutines.CoroutineDispatcher
import kotlinx.coroutines.Dispatchers
import kotlinx.coroutines.withContext
import org.koin.core.annotation.Named
import org.koin.core.qualifier.named
import org.koin.dsl.module
import org.koin.plugin.module.dsl.single

class SyncRepository(@Named("io") private val io: CoroutineDispatcher) {
    suspend fun sync() = withContext(io) { /* ... */ }
}

val dispatchersModule = module {
    single<CoroutineDispatcher>(named("io")) { Dispatchers.IO }
    single<SyncRepository>()
}
```

## Layered architecture

A typical Android app has a data layer (network, database, repositories), a domain layer (use cases) and a UI layer (ViewModels). Each layer uses the definition type that matches its lifetime:

| Layer | Classes | Definition |
|-------|---------|------------|
| Data | `OkHttpClient`, `Retrofit`, `AppDatabase`, data sources, repositories | `single` |
| Domain | Use cases, with no state | `factory` |
| UI | ViewModels | `viewModel` |

<Tabs syncKey="koin-style">
<TabItem label="Compiler Plugin DSL">

{/* check: android-libraries-dsl */}

```kotlin
import org.koin.dsl.bind
import org.koin.dsl.module
import org.koin.plugin.module.dsl.factory
import org.koin.plugin.module.dsl.single
import org.koin.plugin.module.dsl.viewModel

val dataModule = module {
    includes(networkModule, databaseModule, serializationModule)
    single<UserRemoteDataSource>()
    single<UserLocalDataSource>()
    single<UserRepositoryImpl>() bind UserRepository::class
}

val domainModule = module {
    factory<GetUserUseCase>()
}

val uiModule = module {
    viewModel<UserViewModel>()
}
```

</TabItem>
<TabItem label="Annotations">

{/* check: android-libraries-annotations */}

```kotlin
import androidx.lifecycle.SavedStateHandle
import androidx.lifecycle.ViewModel
import org.koin.core.annotation.Factory
import org.koin.core.annotation.KoinViewModel
import org.koin.core.annotation.Singleton

@Singleton
class UserRemoteDataSource(private val api: ApiService)

@Singleton
class UserLocalDataSource(private val dao: UserDao)

@Singleton
class UserRepositoryImpl(
    private val remote: UserRemoteDataSource,
    private val local: UserLocalDataSource,
) : UserRepository

@Factory
class GetUserUseCase(private val repository: UserRepository) {
    suspend operator fun invoke(userId: String): User = repository.getUser(userId)
}

@KoinViewModel
class UserViewModel(
    private val getUser: GetUserUseCase,
    private val savedStateHandle: SavedStateHandle,
) : ViewModel()
```

The `@Module` classes of the previous sections load only if something includes them. Assemble them in one module that the app discovers:

{/* check: android-libraries-annotations */}

```kotlin
import org.koin.core.annotation.ComponentScan
import org.koin.core.annotation.Configuration
import org.koin.core.annotation.Module

@Module(includes = [NetworkModule::class, DatabaseModule::class, SerializationModule::class])
@ComponentScan
@Configuration
class AppModule
```

</TabItem>
<TabItem label="Constructor / Classic DSL">

{/* check: android-libraries-constructor */}

```kotlin
import org.koin.core.module.dsl.factoryOf
import org.koin.core.module.dsl.singleOf
import org.koin.core.module.dsl.viewModelOf
import org.koin.dsl.bind
```

</TabItem>

The ViewModel depends on the use case, the use case on the `UserRepository` interface, and only the data module knows `UserRepositoryImpl`. To swap the data source in tests, override the `UserRepository` binding (see [Unit tests](/docs/testing/)). When each layer lives in its own Gradle module, see [Multi-module apps](/docs/platforms/android/multi-module/).

## Implementations per build variant

### With BuildConfig

Choose the implementation in a provider function:

<Tabs syncKey="koin-style">

```kotlin
    if (BuildConfig.ENABLE_ANALYTICS) FirebaseAnalyticsTracker(context) else NoOpAnalytics()
```

{/* check: android-libraries-constructor */}

```kotlin
import org.koin.android.ext.koin.androidContext
```

With annotations, add `AnalyticsModule` to the `includes` of your app module. `ENABLE_ANALYTICS` is a `buildConfigField` set per build type or flavor. `BuildConfig.DEBUG` works the same way. Both implementations are compiled into every variant; only one is created.

### With source sets

To keep debug-only code out of the release APK, declare the same Koin module in each variant source set:

```kotlin
// src/debug/kotlin/com/app/di/VariantModule.kt
val variantModule = module {
    single<Logger> { VerboseLogger() }
    single<NetworkInspector> { ChuckerInspector(androidContext()) }
}
```

```kotlin
// src/release/kotlin/com/app/di/VariantModule.kt
val variantModule = module {
    single<Logger> { CrashlyticsLogger() }
    single<NetworkInspector> { NoOpInspector() }
}
```

```kotlin
// src/main
startKoin {
    androidContext(this@MainApplication)
    modules(appModule, variantModule)
}
```

`src/main` sees one `variantModule` per build, so it compiles in both. Each variant only ships its own implementations and their libraries (use `debugImplementation` for debug-only dependencies).

## UI helpers that need the Activity

Some helpers need the current Activity, not the Application: dialogs, permission requests, anything that uses the Activity theme. An `AlertDialog` built with the Application context fails when it is shown. Declare these helpers in the Activity scope, where `Context` resolves to the Activity:

<Tabs syncKey="koin-style">
<TabItem label="Compiler Plugin DSL">

{/* check: android-libraries-dsl */}

```kotlin
import android.content.Context
import androidx.appcompat.app.AlertDialog
import org.koin.androidx.scope.dsl.activityScope
import org.koin.dsl.module
import org.koin.plugin.module.dsl.scoped

class DialogProvider(private val context: Context) {

    fun confirm(title: String, onConfirm: () -> Unit): AlertDialog =
        AlertDialog.Builder(context)
            .setTitle(title)
            .setPositiveButton(android.R.string.ok) { _, _ -> onConfirm() }
            .create()
}

val dialogModule = module {
    activityScope {
        scoped<DialogProvider>()
    }
}
```

</TabItem>

```kotlin
    fun confirm(title: String, onConfirm: () -> Unit): AlertDialog =
        AlertDialog.Builder(context)
            .setTitle(title)
            .setPositiveButton(android.R.string.ok) { _, _ -> onConfirm() }
            .create()
}

val dialogModule = module {
    activityScope {
        scopedOf(::DialogProvider)
    }
}
```
