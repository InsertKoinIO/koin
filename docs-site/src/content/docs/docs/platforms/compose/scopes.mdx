This page covers the Compose functions that open a Koin scope for a part of the UI tree: `KoinScope`, `KoinNavigationScope`, `UnboundKoinScope`, and the Android `KoinActivityScope` and `KoinFragmentScope`. Inside such a block, `koinInject()` and `koinViewModel()` resolve from that scope. How scopes work and how to declare them is explained in [Scopes](/docs/concepts/scopes/).

Most functions on this page are marked `@KoinExperimentalAPI`. Opt in with `@OptIn(KoinExperimentalAPI::class)`.

## KoinScope

`KoinScope` gets or creates a scope, provides it to its children, and closes it when the Composable leaves the composition.

Declare the scope:

<Tabs syncKey="koin-style">
<TabItem label="Compiler Plugin DSL">

```kotlin
class FeatureScope

val featureModule = module {
    scope<FeatureScope> {
        scoped<FeatureCache>()
        scoped<FeatureRepository>()
    }
}
```

</TabItem>
<TabItem label="Annotations">

{/* check: compose-scopes-annotations */}

```kotlin
import org.koin.core.annotation.Scope
import org.koin.core.annotation.Scoped

class FeatureScope

@Scope(FeatureScope::class)
@Scoped
class FeatureCache

@Scope(FeatureScope::class)
@Scoped
class FeatureRepository(private val cache: FeatureCache)
```

</TabItem>
<TabItem label="Constructor / Classic DSL">

```kotlin
class FeatureScope

val featureModule = module {
    scope<FeatureScope> {
        scopedOf(::FeatureCache)
        scopedOf(::FeatureRepository)
    }
}
```

</TabItem>
</Tabs>

Open it in Compose:

```kotlin
import org.koin.compose.scope.KoinScope

@Composable
fun FeatureScreen() {
    KoinScope<FeatureScope>(scopeID = "feature") {
        FeatureContent()
    }
}

@Composable
fun FeatureContent() {
    val repository = koinInject<FeatureRepository>() // resolved from the FeatureScope
}
```

`KoinScope` has three forms:

| Form | Scope |
|------|-------|
| `KoinScope<T>(scopeID) { }` | Gets or creates the scope with that id, qualified by type `T` |
| `KoinScope(scopeID, scopeQualifier) { }` | Gets or creates the scope with that id and qualifier |
| `KoinScope(scopeDefinition = { createScope(...) }) { }` | The scope returned by the lambda, which runs on the `Koin` instance |

The scope is closed when the Composable is forgotten (it leaves the composition) or abandoned. A root scope is never closed.

### Multi-screen flows

Put `KoinScope` above a `NavHost` to share scoped objects between the screens of a flow, such as a checkout:

```kotlin
@Composable
fun CheckoutFlow() {
    KoinScope<CheckoutFlowScope>(scopeID = "checkout") {
        NavHost(navController, startDestination = CartRoute) {
            composable<CartRoute> { CartScreen() }
            composable<PaymentRoute> { PaymentScreen() }
        }
    }
}

@Composable
fun PaymentScreen() {
    val state = koinInject<CheckoutState>() // same CheckoutState as in CartScreen
}
```

The scope closes when `CheckoutFlow` leaves the composition.

:::note
A `viewModel` declared in the scope is still stored in the current `ViewModelStoreOwner`. Inside a `NavHost`, each destination gets its own ViewModel instance. Share state between screens through a `scoped` object such as `CheckoutState`, or use `sharedKoinViewModel()` (see [ViewModel in Compose](/docs/platforms/compose/viewmodel/)).
:::

## rememberKoinScope

`rememberKoinScope(scope)` binds a scope you created to the composition, without providing it to children. The scope is closed when the Composable leaves the composition:

```kotlin
@Composable
fun FeatureScreen() {
    val koin = getKoin()
    val scope = rememberKoinScope(remember { koin.createScope<FeatureScope>("feature") })
    val repository = koinInject<FeatureRepository>(scope = scope)
}
```

## KoinNavigationScope

`KoinNavigationScope` opens one scope per Navigation Compose destination. It is in `io.insert-koin:koin-compose-viewmodel-navigation`.

Declare the definitions with `navigationScope { }`. It creates a scope qualified by `NavBackStackEntry`:

```kotlin
import org.koin.module.dsl.navigationScope

val appModule = module {
    navigationScope {
        scoped<ScreenStateHolder>()
        viewModel<ScreenViewModel>()
    }
}
```

With annotations or the Constructor DSL, use the same `navigationScope { }` block in a DSL module (with `scopedOf(::ScreenStateHolder)` in the Constructor DSL). There is no annotation for this scope.

Wrap each destination:

```kotlin
NavHost(navController, startDestination = ListRoute) {
    composable<ListRoute> { entry ->
        KoinNavigationScope(entry) {
            ListScreen() // its own ScreenStateHolder
        }
    }
    composable<DetailRoute> { entry ->
        KoinNavigationScope(entry) {
            DetailScreen() // another ScreenStateHolder
        }
    }
}
```

The scope id is `NavBackStackEntry.id`. The scope is not closed when the destination leaves the composition, so it survives while the entry stays on the back stack.

:::caution
Popping the entry does not close the scope either. Koin closes it only if the composition is abandoned, which means discarded before it was applied, not navigated away from. Each entry therefore leaves its scope and instances in memory until you close it.
:::

To end the scope with the destination, wrap `KoinNavigationScope` and tie the close to a ViewModel stored in the entry. A ViewModel is cleared when the entry is popped and survives a configuration change, while the lifecycle of the entry is destroyed by both:

{/* check: android-navscope-dsl */}

```kotlin
import androidx.compose.runtime.Composable
import androidx.lifecycle.ViewModel
import androidx.lifecycle.viewmodel.compose.viewModel
import androidx.navigation.NavBackStackEntry
import org.koin.compose.scope.KoinNavigationScope
import org.koin.core.annotation.KoinExperimentalAPI
import org.koin.mp.KoinPlatform

private class NavigationScopeCloser(private val scopeId: String) : ViewModel() {
    override fun onCleared() {
        KoinPlatform.getKoin().getScopeOrNull(scopeId)?.close()
    }
}

@OptIn(KoinExperimentalAPI::class)
@Composable
fun ClosingKoinNavigationScope(entry: NavBackStackEntry, content: @Composable () -> Unit) {
    viewModel(viewModelStoreOwner = entry) { NavigationScopeCloser(entry.id) }
    KoinNavigationScope(entry, content)
}
```

Use `ClosingKoinNavigationScope(entry) { ... }` in place of `KoinNavigationScope(entry) { ... }`. If you only need the instances to end with the destination, a [ViewModel scope](/docs/platforms/android/scopes/) does it with no wrapper.

:::caution
`KoinNavigationScope` creates its scope in the global Koin instance (`KoinPlatform.getKoin()`), not in the Koin of the composition. It does not work inside `KoinIsolatedContext`.
:::

## UnboundKoinScope

`UnboundKoinScope` provides a scope you manage yourself. Koin never closes it:

```kotlin
@OptIn(KoinDelicateAPI::class, KoinExperimentalAPI::class)
@Composable
fun SessionArea(sessionScope: Scope) {
    UnboundKoinScope(scope = sessionScope) {
        SessionContent()
    }
}
```

Use it when the scope lifetime does not follow the UI tree: a user session opened at login, a scope shared by several composition roots. It is marked `@KoinDelicateAPI`: you must call `scope.close()` yourself, or the scope and its instances stay in memory.

## Android scopes (Android only)

These functions are Android only. `KoinActivityScope` and `KoinFragmentScope` are in `io.insert-koin:koin-androidx-compose`, and `koinActivityInject` is in the Android target of `koin-compose`. `KoinActivityScope` and `KoinFragmentScope` both read the scope of `LocalContext.current`, so the host Activity must implement `AndroidScopeComponent`. Declaring Activity and Fragment scopes is covered in [Android scopes](/docs/platforms/android/scopes/).

```kotlin
class MainActivity : ComponentActivity(), AndroidScopeComponent {
    override val scope: Scope by activityScope()

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContent {
            KoinActivityScope {
                MainScreen()
            }
        }
    }
}

@Composable
fun MainScreen() {
    val presenter = koinInject<MainPresenter>() // resolved from the Activity scope
}
```

`KoinFragmentScope { }` does the same as `KoinActivityScope { }`, despite its name. In a `ComposeView` hosted by a Fragment, `LocalContext.current` is the Activity, so it provides the Activity scope, and it throws if only the Fragment implements `AndroidScopeComponent`. To use the scope of the Fragment, pass it explicitly. `fragmentScope()` closes it with the Fragment:

```kotlin
class DetailFragment : Fragment(), AndroidScopeComponent {
    override val scope: Scope by fragmentScope()

    @OptIn(KoinDelicateAPI::class, KoinExperimentalAPI::class)
    override fun onCreateView(
        inflater: LayoutInflater,
        container: ViewGroup?,
        savedInstanceState: Bundle?,
    ): View = ComposeView(requireContext()).apply {
        setContent {
            UnboundKoinScope(scope = scope) {
                DetailScreen()
            }
        }
    }
}
```

`koinActivityInject()` resolves from the Activity scope at any depth, without a wrapping block:

```kotlin
@Composable
fun DeepNestedScreen() {
    val session: SessionManager = koinActivityInject()
}
```

It fails if `LocalActivity` does not implement `AndroidScopeComponent`.

## Comparison

| API | Scope lifetime | Closed by |
|-----|----------------|-----------|
| `KoinScope` | The Composable | Koin, when the Composable leaves the composition |
| `rememberKoinScope` | The Composable | Koin, when the Composable leaves the composition |
| `KoinNavigationScope` | Until you close it, even after the entry is popped | You. Koin closes it only if the composition is abandoned |
| `UnboundKoinScope` | Yours | You |
| `KoinActivityScope` | The Activity | The Activity scope (`activityScope()`) |
| `KoinFragmentScope` | The host Activity | The Activity scope (`activityScope()`) |
