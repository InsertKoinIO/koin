This section takes you from an empty Kotlin Multiplatform (KMP) project to Android, iOS and Compose Multiplatform with tests. Read it in order, or jump to what you need. To learn by building, go straight to the [walkthrough](/docs/platforms/kmp/walkthrough/).

## How Koin fits

Koin lives in your shared code. You declare your classes in `commonMain`, write one function that starts Koin, and call it once from each platform app. Whatever differs per platform goes in a platform module, which common code reaches through `expect`/`actual`.

<KmpDiagram />

Three rules cover most of what follows:

- **Declare in `commonMain` by default.** Only the classes that truly differ per platform belong in a platform source set.
- **Start Koin once.** A second `startKoin` throws `KoinApplicationAlreadyStartedException` on every target, so each app has a single start point.
- **Keep constructor injection.** Shared classes receive dependencies through their constructors. `KoinComponent` is only for the boundary with code Koin does not create, such as Swift.

## What runs where

Not every artifact supports every target. Check this before you add a target to your project.

| Artifact | Android | JVM | iOS, macOS | tvOS | watchOS, Linux, Windows | JS, wasmJs |
|---|---|---|---|---|---|---|
| `koin-core`, `koin-annotations`, `koin-test` | Yes | Yes | Yes | Yes | Yes | Yes |
| `koin-core-coroutines` | Yes | Yes | Yes | Yes | Yes | JS only |
| `koin-core-viewmodel` | Yes | Yes | Yes | Yes | No | Yes |
| `koin-compose`, `koin-compose-viewmodel`, `koin-compose-viewmodel-navigation`, `koin-compose-navigation3` | Yes | Yes | Yes | No | No | Yes |
| `koin-android*`, `koin-androidx-*` | Yes | No | No | No | No | No |
| `koin-test-junit4`, `koin-test-junit5`, `koin-test-coroutines` | JVM tests | Yes | No | No | No | No |

The [artifacts reference](/docs/reference/artifacts/) lists every artifact. Android has no separate target in `koin-core`: it uses the JVM variant.
